# Landing

`safe-push --to main` queues a lane on the lander (`north-land@nixos-config`, the unit for this repository, whose remote is github.com/tompassarelli/firn). The lander picks every queued lane onto main as one candidate, runs the seconds-long scans, and pushes. Landing takes seconds.

`.safe-push` sets `land.check-local`, `land.inferred = false` and two `land.check` lines that run on the lander before the push: the formatter, and, for a lane that changes a module whose source calls `writeShellApplication`, a build of the derivations that module's configuration references with the module enabled on whiterabbit (`.github/scripts/shell-apps.nix`), because shellcheck runs only inside that build and evaluation alone passes a script it rejects. A lane that changes no such module skips the build. Each `land.after` line (owners, tools/firn cargo test, native, drift, dotfiles, the flake evaluation, flake and host) runs once per landed batch on main under one `landing.capacity` lease. Only the host line runs on the laptop: with `laptop_system_check_gate` on in north's `harness/defaults.toml` it builds nothing and leaves the laptop's toplevel to the delivery-liveness floor, which skips that build when `north land host-gate` finds the toplevel unchanged since its last build or a landing queue still busy. The flake line builds every flake check but the host toplevels on a build host with `/dev/kvm`, and drift builds there each changed host toplevel but the build host's own. A red run bisects the batch and reverts only its culprit lane.

To add a check, add a `land.after` line with the paths it covers; a `land.check` line is for a check that finishes in seconds and cannot be undone after the push.

After a landing, `firn-host-follow` on the laptop pins the overlay to the new main through a landed overlay lane, deploys each remote host and rebuilds the laptop beside them, alarms the proxy once about a host that failed, and tries that host again every 10 min until it runs main: the follower records a host as done with a main only after the host reports that main, nothing a host build reads changed, or the push for it exits 0. A remote host that sets `nexus-hardening.deployKeys` receives a toplevel built on the laptop (`firn-host-push`, north#760) instead of evaluating its own, once main has been quiet for 30 s; other hosts upgrade through their upgrade unit. `firn-host-follow.builder` names the host that evaluates, builds and signs each remote host's toplevel; with none, the follower builds on its own machine and defers while that machine is on battery or its load exceeds its cores (`firn-host-busy`). The laptop rebuilds on a landing of the overlay too, in parallel with the server deploys, unless it changed only `inertPaths` since the laptop's last rebuild.
